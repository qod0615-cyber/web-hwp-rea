## 1. 노드별 세로 상자

| 노드 | top | bottom (= top + 높이) |
|---|---|---|
| 글자 | −(c/2), c = 글자 칸 = round(s·96/7200)px×75 (1100→**1125**, 748→750, 509→525) | top + c → 11pt **[−562, +563]** |

## 2. 첨자 배치의 기준 상자와 제한 (`0x1008e270`)

```
본체 상자  = 본체 노드가 잰 상자 그대로 (top, bottom) — 글자면 칸, 분수·괄호·근호·{}묶음·다른 첨자면 1절의 그 상자
            본체가 없으면(`{}_{2}C`) ∓ f/2
f         = 첨자들을 잰 뒤 마지막으로 설정된 글꼴 높이 (아래첨자 → 위첨자 순으로 잼 → 위첨자 안 가장 마지막 글꼴)
아래첨자 축 = 본체 bottom − MulDiv(f, 20, 100)
위첨자 축   = 본체 top    + MulDiv(f, 25, 100)
제한       아래첨자 상자 top(축 + 아래첨자top) < 0 이면 0 이 되게 내림
           위첨자 상자 bottom > 0 이면 0 이 되게 올림
```
- **제한의 기준 = 아래첨자 자기 상자 전체(1절의 상자)의 위끝/아래끝 vs 줄의 축 0**. 본체 상자가 아니라 줄 축(글자 칸 가운데)과 비교.
- 실측 4건(정상 `x _{1} y` 아래첨자 축 = 563 − 150 = 413 기준):

| 식 | 아래첨자 상자 | 계산 | 축 이동 | 실측 |
|---|---|---|---|---|
| `x _{sqrt {x}} y` | 근호 [−487, 375] | 413−487<0 → 축 487 | +74 HU = **6.2px** | 6px ✓ |
| `x _{bar {x}} y` | [−525, 375] (bar +150) | 축 525 | +112 = **9.3px** | 9px ✓ |
| `x _{1} ^{a ^{2}} y` | `1` [−375,375], f = 509(위첨자 안 2 의 크기) | 축 563−102 = 461 | +48 = **4.0px** | 4px ✓ |
| `x _{{1} over {2}} y` | 분수(748) [−862, 862] | 축 862 | 상자 가운데 +449 = 37.4px | 23px ✗? |

  분수 경우 h 2286 과 PDF 분자·분모 기준선(+263, +1237 HU)이 모두 이 값과 맞으므로 배치는 이 식이 맞음. 23px 는 다른 기준(잉크·분수선 등)으로 잰 값으로 보임 — 분자 기준선은 정상 아래첨자보다 오히려 38 HU 위, 분수선(가운데)은 +449.

## 3. 전체 높이 h 와 baseLine %

```
h        = 루트 줄 bottom − top          (정수 HU, 여백·반올림 없음)
baseLine = 100 − floor( 100 × (bottom − 385) / h )     ; 정수 나눗셈
         = ceil( 100 × (−top + 385) / h )               ; 같은 값
385      = 축에서 기준선까지 거리 = 35% × 1100 (BaseUnit 의 35% 로 추정)
```
- 3466/3466 일치, 385 이외 값·반올림·버림·floor+0 은 모두 탈락.
- 이 계산은 HwpPlugin 에 없음(HwpApp 의 `BaseLine` 쪽으로 추정). 문서 기준선은 축 +385 로, 그릴 때 글리프 기준선(+373)과 12 HU 다름.
- BaseUnit 1100 외 크기 자료가 없어 "35%·BaseUnit" 인지 "고정 385" 인지는 미확정.
